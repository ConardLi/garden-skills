# 惊艳手法库

这份文件回答一个问题：**为什么有的代码视频让人「哇」，有的只是「能动」？**

> 这里写的是**默认做法**，不是每支片子都要遵守的规定。所选风格（styles.md）和内容优先：瑞士编辑风不用回弹弹簧，生成抽象可以固定机位、匀速旋转，安静的片子变化本来就少。全局底线只有 SKILL.md 里那几条。内容来自对 Opus 5.5 发布后公开传播的代码视频（动效作品集、UI 变形、游戏史短片、产品宣传片、像素动画等）的拆解，再加上动态设计行业的通用方法。

## 1. 惊艳公式

观众在信息流里给你 1 秒。留住他们的，是**意外但合理**的运动。拆开看通常有四个因素（权重随风格变化，安静的风格里密度可以很低）：

| 乘数 | 0 分的样子 | 10 分的样子 |
|---|---|---|
| 变化密度 | 一个画面放 3 秒，元素慢慢淡入 | 每一拍都有东西变形、进场、切换，眼睛一直有事可做 |
| 运动质感 | 匀速平移、所有元素同时出现 | 弹簧落定、预备动作、过冲、错峰跟随、快速运动带拖影 |
| 签名时刻 | 每段的强度都差不多 | 有一个瞬间让人想倒回去看：「这是怎么做到的？」 |
| 音画同步 | 背景音乐和画面各走各的 | 撞击、切点、重拍、音效都在同一帧上 |

**统一性是隐藏的第五项**：手法再多，只要颜色、字体、运动性格保持一致，看起来就是「一个作品」；一旦不统一，就成了「模板合集」。

## 2. 节奏结构：时长模板

先定 BPM，再把结构排在小节上。120 BPM 下 1 拍 = 0.5 秒，1 小节 = 2 秒；128 BPM 下 1 小节 = 1.875 秒。

### 15 秒（8 小节 @ 128 BPM ≈ 15 秒，或 8 小节 @ 120 BPM = 16 秒）

| 小节 | 段落 | 做什么 |
|---|---|---|
| 1 | **Hook** | 第 0 帧就在动。一个强烈的图形动作（点炸开成线、字砸进画面、形状变形） |
| 2–3 | **建立** | 视觉系统亮相：配色、字体、运动性格。每拍一个变化 |
| 4–5 | **加速** | 切点变密（每拍 → 每半拍），镜头开始推，元素变多 |
| 5 末 | **吸气** | 最后一拍留空或降速（riser 声上升、画面缩成一个点或停住） |
| 6–7 | **Drop / 签名时刻** | 全片最强的一下：反色、撞击、镜头急推、粒子组字、大变形 |
| 8 | **落版** | 定格到 logo 或一句话，或者无缝回到第 0 帧 |

### 6 秒（Logo sting / 社交平台 bumper）
预备（0–1 秒）→ 爆发（1–2.5 秒）→ 形成（2.5–4.5 秒）→ 定格（4.5–6 秒）。整个片子只有一个想法。

### 30 秒（16 小节 @ 128 BPM）
Hook（1 小节）→ 第一段（4 小节）→ 小高潮（1 小节）→ 第二段（换一种视觉手法，4 小节）→ 吸气（1 小节）→ Drop（3 小节）→ 落版（2 小节）。一定要有**两种不同的速度**，30 秒全程同一个速度会让人疲劳。

### 循环（Loop，4–12 秒）
没有开头和结尾，最后一帧 = 第一帧（位置、速度、方向都一样）。结构是「一次完整的呼吸」：聚 → 散 → 聚。

## 3. 变化密度与呼吸

- **作品集、宣传短片这类快节奏用途**：默认每 0.5–1 拍有一个可见变化；叙事感强或安静的风格可以放宽到每 1–2 小节。没有设计意图却超过 1 秒完全不动的段落，就是「空拍」。`inspect.mjs motion` 会把它找出来。
- **变化有大小之分**：重拍放大变化（切镜头、变形、反色），拍点放中变化（元素进场、位移），八分 / 十六分音符放微变化（闪烁、小抖动、计数器跳字）。三层叠在一起，画面才有层次，而不是一直在「闹」。
- **呼吸是刻意设计的例外**：drop 前的半拍到一拍空白、签名时刻之后的一次慢镜头，都是为了让下一个冲击更强。没有呼吸的片子，听起来就像一直开着最大音量。
- **一次只突出一件事**：同一时刻最多一个主运动，其他元素要么静止，要么跟随。眼睛追不过来的运动等于没有运动。

## 4. 运动质感

### 4.1 弹簧和缓动（默认）
默认情况下，尺寸、位置、圆角的变化用闭式弹簧（`motion.js` 的 `spring` / `springTo`），参数一旦定下就是这支片子的「运动性格」：

| 用途 | 手感 | `{ freq, damp }` |
|---|---|---|
| 按钮、开关、指示条前沿 | 快、利落 | `{ 3.6, 0.8 }` |
| 卡片、容器、镜头 | 默认 | `{ 2.4, 0.75 }` |
| 大字、3D 物体、Logo 定版 | 沉稳，几乎不回弹 | `{ 1.6, 0.95 }` |
| 吉祥物、贴纸、俏皮元素 | 明显回弹 | `{ 2.8, 0.45 }` |

同类元素用同一档。例外：瑞士编辑风用 `snap`、不回弹；像素风按步进；生成抽象和循环里的匀速旋转是对的。一个值要多次改变目标时用 `springTo` 的叠加写法，不要重启弹簧，这样动作是连续的，任意一帧也能单独算出来。

### 4.2 缓动曲线
不用弹簧的地方也别用 `linear` 或者到处 `inOutCubic`。常用三条：`snap`（硬起步、长滑行：版式跳变、擦除）、`glide`（≈ outExpo：到达、镜头落定）、`whip`（甩镜、硬切过渡）。**离场比进场快**：进场 0.4–0.6 秒，离场 0.2–0.3 秒。

### 4.3 动画的十二法则，挑最有用的四条
- **预备（anticipation）**：大动作之前先往反方向收一点（缩小 5%、后退几像素），时长约主动作的 1/4。
- **过冲与落定（overshoot / settle）**：交给弹簧去做。
- **跟随与重叠（follow-through / overlap）**：一组元素错峰出发（`stagger`，30–60 毫秒一个），从中心向外或者沿着阅读方向。
- **挤压与拉伸（squash & stretch）**：快速移动的条状元素，前沿和后沿用两个不同的弹簧（前沿快、后沿慢），移动时自然就被拉长（见 recipes.md 的「前后沿」）。这是高级 UI 动效最常见的手法。

### 4.4 运动模糊与拖影
快速运动没有模糊会显得「卡」，像幻灯片。两种做法：
- 渲染参数 `--subframes 4`（每帧 4 个子帧混合，180° 快门），对所有运动都生效，代价是渲染时间 × 4。
- 只在快速运动的元素上画「拖影」：沿速度方向复制 3–5 份递减透明度，或者在形变时临时拉长。成本低，可控性更强。

### 4.5 步进动画（on twos）
像素、赛璐璐、定格、手绘风格：角色姿势用 `stepped(t, 12)` 量化到每秒 8–12 张，**但镜头和光照保持每帧平滑**。镜头也步进的话，看起来就是掉帧。

## 5. 转场语法

转场是作品集类视频最见功力的地方。**规则：下一个画面要从上一个画面里的某个元素「长」出来。**整支片子选 2–3 种转场，统一成一套语法。

| 转场 | 怎么做 | 适合 |
|---|---|---|
| **形状变形**（morph） | 同一个元素改变尺寸、圆角、颜色，变成下一个状态（按钮 → 加载圈 → 对勾 → 卡片） | UI 动效、产品功能串联，「一镜到底」 |
| **匹配剪辑**（match cut） | 上一镜的圆 = 下一镜的太阳 / 镜头 / 句号；上一镜的线 = 下一镜的地平线 | 叙事和比喻 |
| **穿越**（zoom-through） | 镜头急推进一个字母的孔、一个按钮、一个像素，里面就是下一个场景 | 能量很强，适合放在 drop |
| **遮罩擦除**（shape wipe） | 用场景里的形状（大字、色块、斜线）当遮罩，扫过画面露出下一镜 | 排版类、品牌类 |
| **甩镜**（whip pan） | 镜头在 4–6 帧内横甩，叠加方向性运动模糊，落到下一镜 | 快节奏、换段落 |
| **色块淹没**（color flood） | 强调色从一个点扩散铺满画面，再退开露出下一镜 | 反色 drop、切换色调 |
| **切片 / 百叶**（slice） | 画面切成 N 条，错峰滑走 | 编辑感、杂志感 |
| **文字即窗口**（type as window） | 巨大的字里面是下一镜的画面，字放大到出画 | 片头、标题 |
| **像素化 / 溶解**（shader dissolve） | 着色器按噪声阈值溶解，或者像素块放大后再缩回 | 复古、科技、故障风 |
| **无限缩放**（infinite zoom） | 每一层画面的某个细节就是下一层的全景 | 签名时刻 |

不要用默认的交叉淡化；硬切只放在重拍上，并且要配撞击声。

## 6. 镜头

2D 画面一样有镜头。用一个虚拟相机矩阵（`motion.js` 的 `camera`：中心、缩放、旋转）统一控制，**所有跟随主体的效果都经过同一个世界坐标 → 屏幕坐标的函数**，不要手写屏幕坐标。

| 运动 | 表达 | 写法要点 |
|---|---|---|
| 慢推（push in） | 聚焦、紧张感上升 | 缩放 1.0 → 1.08，整段持续，`inOutSine` |
| 急推（crash zoom） | 冲击、强调 | 4–8 帧内缩放 ×1.5–3，配撞击声和震屏 |
| 拉远揭示（pull out） | 尺度、全貌、「原来是这样」 | 从细节拉到全景，签名时刻常用 |
| 旋转（dutch / roll） | 动感、失衡 | 不超过 ±8°，用弹簧回正 |
| 视差（parallax） | 深度 | 前景、中景、背景按不同系数移动（1.4 / 1.0 / 0.6） |
| 跟随（follow） | 主体在运动 | 相机用比主体慢一档的弹簧追，带一点滞后 |
| 震屏（shake） | 撞击 | `shake(t, hits)`，衰减 0.2–0.3 秒，幅度 8–20px |
| 焦点转移（rack focus） | 注意力从 A 转到 B | 对非焦点层做模糊（Canvas `filter: blur()` 或 WebGL） |

**快节奏用途里，主体在关键时刻通常要占画面高度的 1/3 以上。**Opus 没有镜头指令时会默认固定机位、主体偏小，所以要在分镜里写明镜头。固定机位也可以是一种风格选择（瑞士编辑、生成抽象），但要是有意为之。

## 7. 动态排版

- **极端的尺寸对比**：巨大的字（画面高度的 20–40%）配极小的技术注释（12–16px 等宽字），比所有字都中等大小要高级得多。
- **一屏一句**：同一时刻最多 5–7 个词（中文约 12 个字）。每段文字至少停留：英文 字母数 ÷ 15 + 1.5 秒，中文 字数 ÷ 4.5 + 1.5 秒（在它完全显示之后才开始计时）。快节奏靠的是**减少字数**，不是压缩停留时间。
- **逐字 / 逐词进场**：从基线下方的遮罩里弹上来（recipes.md 的「遮罩逐字」）、错峰 30–50 毫秒。中文按字或按词拆，不要按笔画。
- **字是图形**：字可以当遮罩、当容器、当网格、被切开、被拉伸、变成粒子。可变字体可以直接动画字重（`font-variation-settings`）。
- **左对齐 + 网格**：居中大字是 AI 默认风格的头号标志。试试左对齐、贴网格、出血（字被画面边缘裁掉一部分）。
- **数字要跳**：计数器用缓动滚动，配 tick 音效，在终值上用弹簧砸一下。
- **字体**：展示字体要有性格（Archivo、Space Grotesk、Syne、Unbounded、Instrument Serif、Fraunces 以外的衬线体、JetBrains Mono 做注释）；中文用思源黑体 / 思源宋体 / 站酷系列这类可商用字体，按用到的字做子集（见 stack.md）。

## 8. 配色

- **2 + 1**：背景色、主色，再加一个只给「主角」用的强调色。主角是唯一带强调色的元素，所以它一出现观众就知道该看哪里。
- **浅色背景被严重低估**：一份对上千支公开 Opus 5.5 视频的色彩统计里，动态图形 / 界面类有 57% 是深色中性、43% 是浅色中性。浅色并不少见，而且浅色（暖灰、米白、纸色）更容易做出编辑感和高级感，也更能跳出 AI 默认的「深色科技风」。
- **反色是现成的 drop**：在重拍上让背景和前景互换 1–2 拍，几乎不花成本就有冲击力。
- **颜色可以当节奏**：强调色随段落变化（每 4 小节换一个色相，相邻色相过渡用 OKLab 插值，即 `motion.js` 的 `mix`）。
- **品牌色优先**。用户给了品牌色就用品牌色，需要更多颜色时在 OKLab 里推导明暗，不要凭空发明新的色相。

## 9. 质感层

质感是「高级」的最后 10%，但用错了会很廉价。

| 质感 | 做法 | 什么时候用 | 代价 |
|---|---|---|---|
| 胶片颗粒 | `render.mjs --grain 4–8`（在 ffmpeg 里加，不画在页面上） | 编辑感、电影感、浅色背景 | 几乎没有 |
| 运动模糊 | `--subframes 4` | 快速运动多 | 渲染时间 × 4 |
| 超采样 | `--dpr 2` | 细线、小字、3D 边缘有锯齿 | 渲染时间约 × 3 |
| CRT / 扫描线 / 弧面 | WebGL 后期（recipes.md） | 复古游戏、终端 | 中等 |
| 色差（chromatic aberration） | WebGL 后期，只在撞击的 2–4 帧加强 | 冲击、故障 | 中等 |
| 半调 / 网点 / 抖动 | WebGL 后期或 Canvas 像素操作 | 印刷感、复古 | 中等 |
| 光晕（bloom） | Three.js 后期或 WebGL 模糊叠加 | 3D、霓虹，**只给发光体** | 中到高 |
| 景深 | Three.js 后期或分层模糊 | 3D 产品、微距 | 高 |

**不要在页面里逐帧画噪点**：每一帧都不可压缩，编码又慢又糊。用 `--grain`。

## 10. 签名时刻菜单

全片只放一个，放在 drop 或情绪最高点。要选能被一句话描述的那种：

- **粒子组字**：几千个点从混沌中聚成 logo 或一个词，再炸开（recipes.md 的「粒子组字」，无状态写法）。
- **一镜到底的形变链**：一个形状连续变成 8–12 个 UI 状态，从不切镜头，每次变形都卡在拍点上（twoclipping 的 UI 变形模板就是这个思路）。
- **无限缩放**：每一层的一个细节就是下一层。
- **穿越进字母**：镜头冲进标题的一个孔，里面是下一个世界。
- **媒介切换**：同一个主体，从像素 → 矢量 → 3D → 手绘，每拍换一种（游戏史短片的手法）。
- **3D 文字挤出 / 爆炸图**：平面字在重拍上挤出成 3D，绕一圈再拍平。
- **液态 / 着色器转场**：画面像液体一样流动着融进下一镜。
- **数据爆点**：一个数字从 0 滚到终值，最后一位落定时整个画面反色、震屏。
- **分屏复制**：同一个动作在 2 → 4 → 16 格里错帧重复。
- **镜面 / 万花筒**：画面在一拍内对称复制成万花筒。

## 11. 禁止清单：AI 默认味及替代方案

每支片子的 brief 里都要写具体的禁止项，从下面这份默认清单里挑适用的，再加上这支片子特有的：

| 默认味 | 为什么廉价 | 改成 |
|---|---|---|
| 深色背景 + 居中大字 + 渐变 | 没有任何约束时 Opus 最容易出来的样子 | 浅色背景或品牌色背景；左对齐网格；巨大的字出血 |
| 所有元素同时淡入淡出 | 没有层次、没有重量 | 错峰 + 遮罩进场 + 弹簧；离场比进场快 |
| 紫 → 粉 → 蓝渐变、到处发光 | AI 科技风的训练集平均值 | 2+1 配色；光只给真正发光的东西 |
| 通用粒子爆炸、镜头光晕 | 模板感 | 粒子必须有目的（组字、跟随、形成） |
| 匀速平移 | 机械 | 弹簧 / glide |
| 无意的机位固定、主体很小 | 画面空、没有能量 | 用镜头运动或版式变化制造能量；主体够大 |
| 角落里的 HUD 标签、细边框、伪数据 | 装饰性噪音 | 删掉；注释只在有信息时出现 |
| 满屏小字、长句 | 手机上看不清 | 一屏一句，字号 ≥ 画面高度的 4% |
| 弹跳缓动（bounce）到处用 | 廉价、玩具感 | 弹簧的阻尼 ≥ 0.6，只给俏皮元素 |
| emoji 当图标、SVG 画的人脸 | 业余 | 抽象图形；需要人物就走绿幕方案 |
| Inter / Roboto / Arial 做展示字体 | 像 demo 页面 | 有性格的展示字体 |
| 循环的接缝处跳一下 | 一眼就能看出来 | 最后一帧 = 第一帧，包括速度 |

**例外**：品牌规范本身就这样用（比如品牌就是深色 + 霓虹），或者用户明确要求。这时候它就是品牌的签名，不是 AI 味。
