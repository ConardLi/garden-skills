# brief.md 模板

`brief.md` 有两个用途：这次制作严格按它来；以后换主题、换工具复用时，它就是一份完整的结构化提示词。用 XML 标签分块，Claude 能更准确地分清哪部分是要求、哪部分是素材、哪部分是约束。

填写要求：首次需求确认之后才写。已确认内容写实，不留【】；必填项不使用未获确认的默认值。推断的受众、平台和建议的技术规格注明依据。API 只记 provider、模型、音色和环境变量名，不记录凭据。

```text
<role>
你是一位动态设计师兼创意程序员，用代码制作可以发布的视频，保留短片的动效表现力，长片按内容节奏分章组织。
</role>

<inputs>
主题：……
观众记住的一句话 / 一个画面：……
素材：……（文件路径；参考视频只学结构和手法；用户的曲子写明授权）
规格：…秒（≤1200，严格 / 允许浮动…秒）· 横屏/竖屏 · …×… · …fps
制作过程预览：启用 / 未提出；用户反馈依据……；进度页链接……（启用时按 progress.md 更新阶段成果）
受众 / 平台：……（用户提供 / 根据……推断）
内容依据：……（用户具体描述 / 用户口播稿 / 资料 / 调研来源；哪些素材由 AI 生成）
品牌：主色 #…，强调色 #…，字体 …（文件在 fonts/）
BGM：AI 合成 / 用户提供 / 关闭；引擎或文件……；声音方向……
音效：AI 合成 / 用户提供 / 关闭；引擎或文件……；动作与声音对应……
口播：无 / TTS / 用户录音
（有口播时填写）用户原稿/录音路径：……；来源：用户；原稿不改写
（TTS 时填写）provider / model / voice：……；配置环境变量名：……
（有口播时填写）真实时长：……；句段时间轴：audio/narration.json；对齐来源：TTS 分段实测 / SRT / 转录工具
（有口播时填写）混音：人声优先；BGM 与音效各自的音量、避让和密度……
</inputs>

<confirmations>
需求确认：用户已确认的摘要、日期/消息依据……
风格帧确认：用户选中的方向、声音方向与确认依据……（第 3 步确认后填写）
最终预览与导出确认：工作区链接、当前版本、反馈与修改、用户点击导出或对话确认的依据……（第 6 步后填写）
若用户明确免除某次确认：记录原话及免除范围，不把「给我惊喜」当作免确认。
时长冲突及处理：无 / ……（冲突须用户确认；不擅自裁切、变速或改稿）
</confirmations>

<direction>
Reel Read:
  format: …（用途，formats.md）
  benchmark: …（对标作品 · 学什么 · 不学什么；有参考视频时写上 inspect grid / heat 量到的数：BPM、段长序列、每段运动面积）
  structure: …（三个候选结构 → 选中的那个和理由）
  style: …（styles/<slug>.md，写明改造点；或混搭方案；或按 _template.md 写的自定义规则）
  signals: …（从风格文件「辨识信号」里挑的 2–3 个，为什么跟这个主题有关；对照「最俗的版本」翻掉了哪几条，或者为什么保留）
  hook: …
  signature: …（记忆点：第几秒，什么手法）
  visual-language: …
  palette: 背景 #… / 主色 #… / 强调色 #…（只给主角用）
  type: 展示 … / 辅助 …
  motion: 弹簧 {freq …, damp …}（大字）/ {…}（UI）；缓动 …；是否步进
  camera: …（按风格和内容选择；长片写明章节间如何变化，口播段不为凑动作打断讲述）
  texture: …
  sound: …（无声；或者：声音对标 · 角色 · 律动 · 和声 · 配器 · 曲线 · 动机 · 混音，能推出来的写一个词即可，见 sound.md 第 2 节；用户曲子写 BPM 和 drop）
整片只用一套视觉系统；同一个元素在每个镜头里的样子保持一致。
每个镜头有一个清楚的理解重点。展示文案精简并停留到能读完；不用把每句口播抄上屏。镜头可以跨多句，主体、空间与动作随内容连续发展。
运动方式按所选风格（弹簧、snap、步进或周期运动）；转场从画面内容里长出来，不用默认的淡入淡出。
禁止：……（针对这支片子写具体的，比如：深色背景 + 居中大字 + 渐变；所有元素同时淡入；紫蓝渐变和发光；角落里的 HUD 标签；匀速平移；Inter 做展示字体；有声片也可以写声音的，比如 Am–F–C–G 循环、每个重拍都 impact + crash，见 sound.md 第 12 节）
</direction>

<structure>
（无口播）节拍网格：BPM …，共 … 小节（… 秒）；重拍 = 大变化，拍点 = 中变化，八分音符 = 微变化
| 小节.拍 | 段落 | 画面（含原文文字） | 运动 | 镜头 | 声音 | 转场 |
|---|---|---|---|---|---|---|
| 1.1–2.4 | Hook | … | … | … | … | … |
| … | … | … | … | … | … | … |
（有口播时，用此表替代音乐节拍表；先写预计区间，实际口播准备后回填真实区间）
| 镜头 / 关联句段 ID | 要解释的变化 | 对象起止状态 | 继承的对象与空间 | 事件 / 实测时间依据 | 镜头 / BGM / 音效 | 衔接方式 |
|---|---|---|---|---|---|---|
| … | … | … | … | … | … | … |
句段到镜头可以多对多；原稿保留在输入文件，分镜不用重复全文。关键事件共用同一个时间变量；无实测词时间时只能声明句级同步，不能按字数均摊。
（超过 2 分钟）章节表：各章项目路径、全片起点、章内时长、衔接方式；章节时长之和等于确认时长；字体、品牌色、重复元素保持一致。
签名时刻：…（小节.拍，以及具体怎么做）
结尾：落版 … / 无缝循环
</structure>

<build>
1. 短片保留单个 HTML 文件（或说明为什么需要 Three.js / p5）；长片按 long-form.md 拆章节。内容层：…，质感层：…。
2. 页面暴露 window.DUR / window.render(t) / window.READY；画面只由 t 决定，随机数带固定种子，不用计时器，不用 CSS 动画，帧和帧之间不保存状态。
3. 所有时间点写在 timeline.js，页面和 score.mjs 都从它 import；镜头表写进 SHOTS；无口播时，要对拍的转场用 revealOn(拍点, 时长, 揭开点) 倒推起点。有口播时先合成或分析真实音频，再用句段时间戳定镜头，不用估时冒充对齐。
4. 渲染：render.mjs 逐帧截图 → ffmpeg；参数：--fps … --size … [--subframes 4] [--dpr 2] [--grain …]。
5. BGM、音效分别取确认的来源，保留第 1 档 score.mjs / 第 2 档 score.tone.js。口播按 narration.md 准备；独立轨用 narration.mjs mix，最终混音统一响度与峰值。有音效的动作落在动作那一帧；有口播时收敛配器与音效。三轨都关闭才写「无声」。长片音频按章构建，不用整片 Float32 合成代替分段处理。
6. 每个镜头做完渲 3 张静帧检查；关键状态变化和镜头接缝在工作区连续播放，检查事件同步与动作承接。全部完成后跑 --determinism，主动打开 editor.mjs 工作区供用户预览，不先出低清 MP4；用户确认当前版本可以导出后再出正片。
7. 用户确认预览通过后导出并验收：工作区导出，或未改音轨时 sh build.sh（FPS / SIZE / AUDIO / LOOP 写在 build.sh 顶部，时长取 timeline.js 的 DUR），等价于 inspect.mjs qa --expect-size … --expect-fps … --expect-duration … --audio required|none [--loop]；技术检查全部 PASS，且没有 NOT CHECKED。timeline.js 里声明 HOLDS（刻意的停留）和 DROPS（要留呼吸的重拍）。build.sh 还会出文字框景（qa/text.json）和按镜头的运动报告，这两份是审片材料，每一条都要看过。
8. 混合音轨使用 AUDIO=file AUDIO_FILE=audio/final.wav sh build.sh；长片使用 build-long.mjs chapters.json，保持章节缓存。有口播时检查 narration.json 和实际音频时长、逐句声画对应、原稿完整性；长片逐章检查并复核接缝。
</build>

<gotchas>
……（这支片子特有的坑，比如：字体加载完再 READY；WebGL 先渲一帧确认生效；中文字体要子集化；循环片首尾帧完全一致；被缩放的文字不加 will-change）
</gotchas>

<start>
（按情况只保留下面一段）
【要确认 · 默认】需求已确认，才进入本 brief。已定风格：先出 hook、记忆点、结尾三张风格帧给我确认；未定风格：先给 3 个拉开差距的方向，各一张关键帧（render.mjs --directions）让我选。连续动作是核心时同时附代表性运动小样；TTS 给用户原稿的分段方案和音色短样。放在同一次风格确认里，等我回复后再正式制作。
【不用确认 · 用户明确免除风格帧确认】仍先出风格帧，自己看图选一个，把选择和理由写进 brief，然后继续。「你决定」只授权审美选择，不自动免除确认。
之后：有口播先锁定实测时间轴，再按镜头顺序制作，每个镜头完成后自检；画面与混音准备好后默认打开 editor.mjs 工作区（长片逐章预览），等我确认当前版本可以导出后才生成 MP4。工作区音频编辑随当前会话导出；没有音轨编辑时短片也可用 build.sh，长片按 long-form.md 用 build-long.mjs。技术检查全部 PASS、没有 NOT CHECKED 后，附上审片记录交付。
</start>
```
