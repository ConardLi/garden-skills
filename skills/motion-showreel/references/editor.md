# 默认剪辑工作区

所有制作默认先在这里预览、调整独立音轨，用户确认当前预览通过后再生成 MP4。Agent 应主动启动服务并打开工作区；不能打开浏览器时提供本机链接，等待用户反馈。无声、无口播、短片、循环片都适用，长片按下方说明逐章预览。无需用户额外要求打开编辑器，也不默认生成代理 MP4。

用户点击「导出视频」或在对话中说当前版本可以导出，即为导出确认；不再重复询问。修改内容后应让用户复看。用户明确要求跳过预览、直接导出时可按其指示执行并记录。原有 `preview.mjs` 用于轻量调试，`build.sh`、分章构建与验收继续作为确认后的导出工具，动画与声音的实现不变。

用户在需求阶段表示希望看制作过程时，提前以 `--progress` 打开同一入口，逐阶段发布风格帧、音色短样和可播放成果；见 [`progress.md`](progress.md)。制作阶段只读，最终短片发布 `review --final` 后仍在此页确认与导出。未提出时保留本文的默认最终预览流程。

## 打开已有项目

```sh
node <skill>/scripts/editor.mjs <project> --size 1920x1080 --fps 30
```

打开终端输出的本机网址。尺寸、帧率必须与本片确认规格相同。时长读取项目 `timeline.js` 的 `DUR`，也可用 `--duration <seconds>` 或 `editor.json` 的 `duration` 指定；场景实际 `window.DUR` 不一致时会提示错误。无需先渲染 MP4，也不调用 TTS 或合成配乐。项目没有音频时可以无声预览。

可用 `--audio audio/final.wav` 明确原始混音。已有导出质量设置可传 `--workers`、`--subframes`、`--shutter`、`--dpr`、`--grain`、`--crf`；实时预览不模拟导出器的子帧混合、DPR 超采样或 ffmpeg 颗粒，界面会提示。不要声称这几项已经逐像素匹配。

## 工作区布局

画面和时间线共用一个工作区。默认收起调音与制作进度，给画面留出空间；需要时用顶栏按钮打开。预览工具条支持适应窗口、比例缩放、放大后拖动、Ctrl/⌘ 滚轮缩放和最大化，Esc 还原。拖动画面与时间线之间的横向分隔条可分配上下空间；分隔条也支持方向键与双击复位，轨道较多时在时间线内部滚动。所有显示操作只改变预览布局，保留原场景尺寸、时间轴与导出参数。

## 第一版支持的操作

- 原场景在固定宽高的独立 iframe 内运行同一个 `render(t)`。画面轨显示 `SHOTS`，播放头可拖动，支持逐帧、时间线缩放与循环试听选区。复杂场景可能实时掉帧，不改变离线导出的帧数。
- 真实音频波形，按项目源文件生成并缓存；口播、BGM、音效分别显示。静音、音轨增益会计入导出；增益调的是轨间比例，编辑后的最终混音仍按原验收标准统一到 −14 LUFS。
- BGM 和音效片段可拖动、切分、裁剪、移除，设置源入点、时长、片段增益和淡入淡出。切分点在淡入淡出区间内时会提示调整，避免切分意外改变声音包络。片段之间允许重叠，重叠处相加。
- 口播与已有整段混音的时间位置锁定，可调增益或静音，不能剪字、移动或改变速度。画面、字幕和语义时间戳保持绑定。循环选区只用于试听，不裁切最终导出。
- 撤销、重做、自动保存和刷新恢复。保存文件为 `.showreel-editor/session.json`，不修改动画、用户原稿或音频；源音频变化后不会自动套用旧编辑。原文件及旧会话保留在磁盘。
- 音频有改动后点击「更新试听」，或直接播放时自动更新。只重新混音，不渲染视频；播放的是导出将使用的同一份 WAV，不使用另一套近似的浏览器混音。长片混音仍需要等待，结果按编辑内容和源文件签名缓存。

## 音轨从哪里来

优先读取项目根目录 `editor.json` 的明确轨道配置；否则读取 `audio/mix.json` 的各输入轨、增益和人声避让区间。新生成的 mix 记录会附带增益，旧记录未记录增益时界面会说明默认值，必要时用 `editor.json` 填入原值。**未编辑状态始终直接播放原始最终混音，不重新处理它。**

只有 `audio/final.wav` 或合成后的 `audio/music.wav` 时，按一条已混合轨显示，不能声称能恢复独立口播、BGM 或音效。可在生成音频时保留独立文件，再显式配置：

```json
{
  "duration": 60,
  "size": "1920x1080",
  "audio": "audio/final.wav",
  "tracks": [
    {"id": "voice", "kind": "voice", "file": "audio/narration.wav", "gain": 1},
    {"id": "bgm", "kind": "bgm", "file": "audio/bgm.wav", "gain": 0.35},
    {"id": "sfx", "kind": "sfx", "file": "audio/sfx.wav", "gain": 0.5}
  ]
}
```

轨道类型为 `voice`、`bgm`、`sfx`、`mix`，路径相对项目目录。内置合成器的 `audio.mjs build score.mjs --stems` 可导出总线分轨，但总线不必等同于 BGM/SFX，混响与母带也可能集中在总混音；须按真实内容配置，不能把分轨相加就宣称还原原混音。工作区最多 32 轨、256 个音频片段。

第一版针对单个 `render(t)` 页面，多页面长片先逐章打开工作区预览、检查相邻章节的承接，用户确认后才运行原章节构建器；不假称支持整片跨页面连播或自动汇总多章音频编辑。同一页面的不同区间构成多章时，打开该页面，用循环选区定位各章，不通过缩短 `--duration` 改变场景时长。工作区中的声音修改必须同步到实际导出所使用的混音及校验记录，不能在长片拼接时丢回原混音；具体见 `long-form.md`。

## 导出与兼容

界面中只有点击「导出视频」才启动原来的 `render.mjs`，先检查确定性，导出后运行完整规格的 `inspect.mjs qa`，并生成文字审片材料。阶段、实际帧进度和错误在界面显示，支持取消；失败或取消的任务不会发布成片。用户在对话中确认导出时，Agent 可操作该按钮；未在工作区编辑声音时，也可调用已确认规格的原构建命令。图像仍需按 `review.md` 审片，技术验收不替代用户终审。

输出为新的 `out/editor-<task-id>.mp4`，不会覆盖 `out/final.mp4`。该任务使用的编辑快照、验收与审片材料保存在 `.showreel-editor/exports/<task-id>/`。原有 `build.sh` 不自动读取工作区编辑；重建该编辑版应在工作区再次导出。要把编辑混音用于其他构建，须同时同步音频路径和有效混音校验记录；仅改 `AUDIO_FILE` 会与原 `audio/mix.json` 不匹配，不能跳过校验。

服务仅监听本机，关闭终端服务后停止访问。源文件、代码和编辑记录均留在项目目录，无远端账号或新 npm 包。回归测试：

```sh
node --test <skill>/scripts/test/editor-model.test.mjs <skill>/scripts/test/editor.test.mjs
```
