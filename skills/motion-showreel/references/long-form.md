# 长片：章节、构建与审片

适用于超过 2 分钟、最长 20 分钟的视频。短片仍走原来的单页面与 `build.sh`，无需为了新能力增加项目复杂度。

## 先规划内容，再分章节

需求确认时明确总时长和是否允许浮动。口播实际时长与目标不符时先确认；超出 1200 秒也不能自动裁掉。TTS 必须使用用户原稿；没有口播时仍可用节拍驱动，保留现有全部风格和合成引擎。

brief 写清章节目的、时长、衔接和贯穿元素。长片可以有多个重点，不必把短片的高速变化密度持续二十分钟。字体、色彩、图形含义保持一致，变化服务于讲述。风格帧按主流程：已定风格出三帧，未定风格给三个方向；确定后可增加各章代表帧自检，不额外增加必停确认。

按内容边界拆章，通常每个构建单元 30–90 秒；这是控制渲染和音频内存的建议，不是叙事规则。每章用独立项目目录与本地时间轴，从 `render(0)` 开始；总片时间 = 前面各章时长之和 + 章内时间。共享的设计 token、素材和构建依赖要列入各章的 `inputs`，避免缓存漏掉外部变化。

构建单元不等于视觉段落。章内 `render(0)` 不意味着把主体、位置和运动重置；分片承接同一个动作时，使用共同的全片时间/轨迹或显式衔接姿态。叙事段落切换允许有意的硬切，不能让技术切片制造随机停顿和空间跳变。口播句段也不要求逐句切镜。

## 可重建的章节清单

在项目根写 `chapters.json`，所有路径相对此文件。时长以秒计，章节按数组顺序拼接：

```json
{
  "version": 1,
  "duration": 180,
  "size": "1920x1080",
  "fps": 30,
  "chapters": [
    { "id": "intro", "project": "chapters/intro", "start": 0, "duration": 60, "audio": "chapters/intro/audio/final.wav" },
    { "id": "explain", "project": "chapters/explain", "start": 0, "duration": 60, "audio": "chapters/explain/audio/final.wav" },
    { "id": "end", "project": "chapters/end", "start": 0, "duration": 60, "audio": "chapters/end/audio/final.wav" }
  ],
  "render": { "workers": 3 }
}
```

`start` 是源页面的章内取帧起点，不是最终视频中的开始时间。也可以让多章引用同一页面并用不同 `start`，但共用源代码变更时，这些章会一起失效。章节时长应落在帧边界，总和必须等于确认时长。

```bash
node <skill>/scripts/build-long.mjs <slug>/chapters.json
```

同一命令再次执行会复用通过校验的章节缓存；更改某章源文件或渲染规格后，只重建失效章节。保留 `.showreel-cache/`，不要把正常中断当作清空缓存的理由。内部缓存是技术产物，不代替源码、brief 和原始音频。

- 每章保留独立音轨：使用 `chapters[].audio`，缺音轨的章补等长静音。章音轨时长冲突会报错。
- 已有整片混音：改用顶层 `audio` 指向整片音频，不再设置任何 `chapters[].audio`。它必须与确认的总时长匹配。
- 全片无声：两种音轨字段都不设置；技术检查要求没有音轨。短片对应 `AUDIO=none`，不要把静音 WAV 当作需要通过响度检查的有声成片。
- `--skip-qa` 只用于草稿，不能作为交付构建。最终必须用完整规格通过验收。

## 音频也按章制作

内置合成器和 Tone.js 都会分配整段采样内存。不要为 20 分钟整片建立多条 Float32 bus，再试图靠增加内存完成。

每章写自己的 `timeline.js`、`score.mjs` 或 `score.tone.js`，沿用原有音色、效果和卡点工具。先用 `audio.mjs build` 构建本章音乐/音效，再按 `narration.md` 与本章口播混音，得到本章 `audio/final.wav`，最后由章节构建器流式拼接。

用户提供整段口播时，先获得真实句段时间戳，再在自然停顿处分章；切分不得丢字或改变速度，所有章区间必须覆盖确认过的完整内容。原始录音保留。用户原稿很长时，TTS 自带按句段合成与缓存；按章节选择相应片段制作画面。整片音轨可以保留在顶层，避免重复编码人声。

配乐在章边界处预先设计延续、淡出或呼吸，不能把章节拼接当成任意截断音乐的理由。连续音乐可先用流式 ffmpeg 拼接处理，最终统一做母带；不要对本应安静的章节各自强行拉到同一响度。人声期间的避让与最终混音见 `narration.md`。

## 分章验收与全片验收

构建前对各章跑 `render.mjs --determinism`；每章做静帧、文字框景、运动与手机尺寸检查，材料按 `qa/<chapter-id>/` 保存。对每个切点前后看连续帧，检查重复帧、漏帧、文字跳变和音频接缝。

构建器对全片运行 `inspect.mjs qa`，检查尺寸、帧率、总时长、帧数和最终音轨。全片抽帧只是目录，不能代替逐章检查。口播另跑 `narration.mjs check` 并逐句核对原稿、声音和画面；整片听感仍交给用户终审。交付章节清单、缓存复用方式、重建命令、技术结果和已知问题，不宣称仅凭抽帧已完整观看或听过全片。
