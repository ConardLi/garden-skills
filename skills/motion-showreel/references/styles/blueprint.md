# 工程蓝图（blueprint）

> 轮廓、尺寸线和剖面逐层出现，把一个对象怎样组成、怎样配合讲清楚。
> 参照（只学语法）：晒图工艺、工程制图、建筑图纸与装配说明。不照搬具体工程图、产品结构和机构标识。
> 借鉴方向：[lemo-opuscar 的 Blueprint](https://github.com/lemomo-ai/lemo-opuscar/blob/main/styles/blueprint/STYLE.md)，按本库结构重新整理，技术实现由 Agent 按主题探索。

## 本质 / 不是什么

- 本质：**用投影与制图层级解释结构**。实线说明可见边，虚线提示隐藏部位，尺寸与引线把关系交代清楚；画面首先是一张能读懂的图，再带有晒图的纸墨质感。
- 不是：`copperplate-engraving` 的白线版本，也不是 `hologram-hud` 的平面截图。蓝图的排线表示剖面区域，通常不靠密集随形排线塑造明暗；信息依附图纸坐标，不悬浮在三维空间里。

## 辨识信号：每支片子挑 2–3 个

| 信号 | 长什么样 | 适合的主题 |
|---|---|---|
| 多视图对齐 | 正视、侧视或俯视共用投影基准 | 产品、建筑、组成 |
| 尺寸链 | 尺寸线与延长线分层排在物体外 | 比例、规格、精确关系 |
| 线型分工 | 可见边、隐藏边、中心线有不同线型 | 结构、内部关系 |
| 剖切窗口 | 局部外壳让出位置，露出带排线的截面 | 原理、材料、内部 |
| 爆炸装配 | 零件沿装配轴分开，彼此仍对得上 | 工艺、模块、协作 |
| 局部详图 | 一个节点被放大，旁边标出对应位置 | 精密连接、重点功能 |
| 图框与标题栏 | 图名、版本、比例说明有固定位置 | 方案、迭代、档案 |
| 修订云线 | 改动区域被圈出，旧版与新版有对应 | 更新、对比、纠错 |
| 构造辅助线 | 几何基准先出现，成图后部分退去 | 从想法到结构、方法 |
| 晒图边缘 | 蓝色纸面有很轻的曝光差异与折痕 | 制作、历史、实体图纸 |

规则：

- 每支挑 2–3 个，至少一个不在下面「最俗的版本」里；信号从主题里选。
- 数字、比例、零件关系必须有依据。没有工程资料时明确标「示意」，可以省掉数值，不能用随机尺寸装出专业感。

## 这个风格最俗的版本

- 画面：蓝底网格、白线从左扫到右，正中一个机械物件，四周密密麻麻的尺寸和无意义编号。
- 声音：画线必配电流声，数字跳动必配滴声，完成时来一下金属撞击。
- brief 的 style 一栏写明翻掉了哪几条，或者为什么保留经典版。可以用无网格的局部详图、修订对比或图纸折叠建立重点。

## 适配

- 用途：产品原理讲解、结构展示、方案比较、工艺宣传、技术片头。
- 内容：建筑、工程、模块化服务，以及能诚实表达为结构关系的概念。
- 不适合：需要照片级材质判断的产品片、情绪主导的生活片，或把未知内部结构包装成事实的讲解。

## 技术路线

- **平面制图**：SVG、Canvas 都可；DOM 可承载独立的标题与说明。路径求交、剖面裁切可考虑 Paper.js，线型与文字层级按本片图纸设计。
- **多视图与装配**：若有授权模型，可探索 Three.js 正交相机、边线与剖切表现。多视图尽量来自同一个几何对象，避免手画三张彼此矛盾的图。
- **纸面质感**：用局部纹理或轻量着色器表达晒图密度，PixiJS 可辅助遮罩；信息层先保持清晰，再加纸纹。
- 任意时间独立恢复零件位置、引线端点与显现状态；纸纹固定种子。`--dpr` 以虚线和小字可读为准，`--subframes` 从轻，`--grain` 不得破坏虚实线差别。

以上是可选路线；不预设 CAD 引擎、图纸标准或具体绘图代码，涉及专业标准时按资料采用。

## 材质与渲染

- 工艺依据：传统蓝晒复制通过曝光与水洗留下蓝色底和浅色线。印好的图纸是平面材料，线本身不发光。
- 可见轮廓最醒目，尺寸与辅助线次之，网格最弱。线宽有可见差别，不能靠一堆近似白线让观众猜层级。
- 剖面排线在同一材料区域内方向和间距稳定，边界裁切干净；相邻零件可用不同方向区分，不把它当立体明暗。
- 尺寸文字留在线的上方或断口内，引线终点准确贴住对象。镜头移动时，文字与图纸一起移动，不在屏幕上漂浮。
- 折痕和曝光差只轻微影响底纸；前景主体也遵守制图线型，不在蓝图中间贴一张写实渲染图。

## 配色

下面的色值是示例，看思路，不要原样照抄。

- 深蓝晒图：底 `#153C68` / 主线 `#E5F0EB` / 修订 `#EDBB72`。
- 浅底工作图：底 `#E8EEEA` / 主线 `#244B66` / 修订 `#B34E40`。
- 暗青方案图：底 `#163F46` / 主线 `#D7E9DD` / 强调 `#E5C06D`。
- 推导：底色从品牌色里取稳定的暗色或低饱和浅色，线与底保持反差。强调色只表示当前剖切、选中或修订的一类信息，并在全片保持同义。

## 字体

英文和数值可选 IBM Plex Mono、Roboto Mono，中文用思源黑体，自托管 OFL 字体。数字保持等宽，单位与数值留出间隔。标题比标注大一档，标注先按最终手机尺寸定字号，再决定一镜能容纳多少条尺寸。

## 运动

- 图形显现按理解顺序组织：可以先给整体轮廓，再揭示某一连接；不必每次从网格开始。
- 爆炸装配沿真实或明确的示意轴移动，起止位置能对合。零件运动平稳，几乎不回弹，避免变成玩具散落。
- 尺寸线在对应结构稳定后出现，更新结构时同步更新标注。离场可换视图、收起剖切或翻到下一版图纸。

## 画面怎么活

- 图纸阅读时以静为主，已完成的尺寸与轮廓不闪烁。
- 讲机械关系时，一个机构缓慢走完小幅工作行程，中心线与连接点保持一致。
- 修订场景可让剖切面缓慢移动，或让局部详图的观察范围沿对象平移；每次只让一个重点变化。

## 镜头语法

| 镜头运动 | 表达什么 | 适合哪类内容 |
|---|---|---|
| 垂直图纸的固定机位 | 客观、方便比较 | 尺寸、结构、版本 |
| 从全图推到一个节点 | 解释关键连接 | 产品细节、原理 |
| 沿投影线从一个视图移到另一个 | 同一对象的不同观察面 | 建筑、多视图 |
| 固定尺度，图层依次展开 | 各层如何配合 | 装配、模块、剖面 |

## 声音调色板

第 1 档可用短促的木质敲击、低音脉冲和少量干燥噪声，分别对应定位、移动和图层切换。需要铅笔、描图纸、量具拟音时，用第 2 档 Tone.js 配合授权采样。只给有意义的落位配音，尺寸文字出现不必逐字滴响；有口播时压低细碎高频。

律动与和声（举例，不止这些）：均匀而稀疏的脉冲、带停顿的机械节奏，或温和的室内乐分句。技术内容可以有温度，不必统一成警报式科幻音轨。

## 原生手法

- 轮廓完成后，尺寸与引线分组补齐：适合结构建立和片头（经典）。
- 剖切线穿过外壳，露出截面，再转成局部详图：适合内部原理。
- 同一零件在正视与侧视间沿投影基准对应：适合解释空间关系。
- 修订云线包住改动，旧线退去、新线就位：适合版本升级和方案对比。
- 爆炸图沿装配轴收拢，同时让标注归入标题栏：适合从组成走到整体结论。

## 变化空间

- 结构：围绕一个关键节点深入；多视图逐个回答问题；两张方案图并列比较。
- 开场：先出现一条需要解释的剖切线；从局部错配开始；展示完整图纸后拿掉一层。
- 结尾：保留可读的定稿；只留最关键的结构关系；图纸收起，转到下一章的局部。

## 坑

- 随机编号和尺寸看似专业却互相矛盾：依据资料填写，未知项删去或标示意。
- 三个视图形状对不上：共用几何依据，至少核对对应长度与孔位。
- 引线端点随动画脱离对象：端点与对象位置一起求取。
- 所有线一样亮：先拉开轮廓、标注、辅助线的层级。
- 剖面排线穿过空腔：按实体区域裁切，空腔保持空白。
- 镜头缩小后小字无法读：减少同时出现的标注，另开详图，不只提高分辨率。
- 蓝底加发光遮住晒图质感：把光晕去掉，先看图纸是否仍成立。
