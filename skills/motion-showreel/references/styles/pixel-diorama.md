# 像素立体场景（pixel-diorama）

> 平面的像素角色站进有纵深的布景，灯光、遮挡和镜头让这个小世界有了距离。
> 参照（只学语法）：像素精灵与立体场景结合的游戏画面、HD-2D 的空间组织、像素舞台布景。不照搬具体游戏角色、地图、界面、配乐或商标。

## 本质 / 不是什么

- 本质：**像素画的取舍与三维空间的光照同时成立**。角色仍是有限像素组成的平面精灵，地面、前景和远景提供纵深，角色能被挡住，也能在脚下留下对应的影子。
- 不是：`pixel-game` 的纯二维小画布，也不是把普通低多边形场景全屏打马赛克。与 `tilt-shift-miniature` 相比，这里最关键的是像素角色和立体环境之间可信的接触。

## 辨识信号：每支片子挑 2–3 个

| 信号 | 长什么样 | 适合的主题 |
|---|---|---|
| 平面像素角色 | 少量像素簇概括身体，转向时换对应视图 | 角色、旅程、游戏感 |
| 分层立体布景 | 前景遮挡、中景路径、远景轮廓有真实距离 | 世界、探索、空间 |
| 脚底接触影 | 小阴影跟脚的位置和地面高度变化 | 行走、落地、存在感 |
| 像素受光 | 角色亮暗随场景灯光改变，轮廓仍清楚 | 时间、灯光、状态 |
| 低分辨率地表 | 纹理以有意组织的色块表达石、木、水 | 环境、材料、场景 |
| 平面精灵遮挡 | 角色经过柱、树和门时被正确挡住 | 深度、进入、路径 |
| 选择性景深 | 远处变柔，当前角色保持像素结构 | 注意力、尺度、情绪 |
| 像素特效簇 | 火、水花或光点按块变化，跟场景有位置关系 | 魔法、能量、反馈 |
| 前景擦镜 | 近处屋檐或枝叶掠过，露出下一片空间 | 穿行、发现、转场 |
| 步进姿态与平滑镜头 | 角色少帧动作，镜头缓慢连续移动 | 怀旧与空间感并存 |

规则：

- 每支挑 2–3 个，至少一个不在下面「最俗的版本」里；信号从主题里选。
- 先定像素密度与场景尺度，再安排光效。角色、纹理与特效可以不同分辨率，但差异要有依据，不能随素材来源碰运气。

## 这个风格最俗的版本

- 画面：小勇者站在森林村庄中央，火把全开、萤火虫满天飞，强景深和泛光把一切照得梦幻。
- 声音：怀旧冒险配乐加八位拾取音，每进一张地图就响一段胜利旋律。
- brief 的 style 一栏写明翻掉了哪几条，或者为什么保留经典版。现代车站、室内工坊或干燥日光也能体现这种空间语言。

## 适配

- 用途：游戏概念预告、故事向宣传、品牌小世界、探索式片头、氛围循环。
- 内容：角色与环境的关系、旅途、发现、熟悉事物的像素化重述。
- 不适合：真实产品界面复现、密集数字展示，或需要自由近距离环绕精细人物的镜头。

## 技术路线

- **布景与精灵**：Three.js 可组织地形、简单建筑和承载精灵的平面。纹理使用最近邻采样作为起点，角色朝向与相机关系需按镜头单独设计。
- **受光与阴影**：可探索光照材质、简化法线或分层明暗；影子按精灵的不透明轮廓处理，避免透明贴图投出矩形阴影。固定机位也可用手工设计的接触影近似。
- **像素动画**：Canvas、Aseprite 导出的授权图集或自主绘制的帧图都可用作素材；PixiJS 适合平面场景层。库负责显示，像素簇和姿态仍需设计。
- 图集帧、位置、灯光和特效由时间独立确定，随机粒子固定种子。`--dpr` 与内部像素分辨率分开考虑；`--subframes` 从低值试起，避免把步进动作抹成重影；`--grain` 通常关闭。

以上是候选方向，不绑定游戏引擎或某种商业画面方案。

## 材质与渲染

- 制作依据：先画像素精灵与纹理，再把它们放进立体布景。像素是有选择的色块，轮廓的台阶、暗部的簇和留空都应可辨。
- 角色脚底对齐地面接触点，起伏地形同步调整高度与影子；不能让人物像贴纸一样悬在地表上方。
- 平面角色有可见角度限制。镜头绕行过大时，需要换方向帧、改变精灵朝向或重新构图，避免突然变成一条薄边。
- 近景像素保持清楚，远处纹理要防闪烁；不要为了最近邻锐利，把所有远景都保留到无法稳定采样的细节密度。
- 光照能改变色组亮度，但不能冲掉角色识别色。泛光主要给真实亮源与少量特效，正文和主体轮廓保持锐利。

## 配色

下面的色值是示例，看思路，不要原样照抄。

- 日光石城：暗色 `#33485A` / 石面 `#B8B59A` / 植被 `#71845C` / 焦点 `#CC754C`。
- 暖灯工坊：环境 `#293642` / 木色 `#88634C` / 灯光 `#E0B56E` / 角色 `#97B6AE`。
- 冬日站台：环境 `#CBD9D9` / 阴影 `#687E94` / 主体 `#4E626A` / 强调 `#B65848`。
- 推导：分别给环境、角色和亮源分配有限色组，靠明度让角色从背景中分离。品牌色可以落在角色或目的地上，避免每种材料都共用一条万能渐变。

## 字体

英文短标题可用 Pixelify Sans，辅助用 IBM Plex Sans；中文优先用思源黑体，自托管 OFL 字体。确需中文像素字时，使用授权清楚、覆盖字表足够的字体。像素字按合适倍数显示，长字幕保持清晰，允许采用独立的平面阅读层。

## 运动

- 角色用少量关键姿态表达重心和方向，走路时足部接触与位移匹配；不能只有整张贴图上下弹动。
- 镜头可平滑，人物可步进，灯光可缓变；三者各有节奏，不把整片强行压成同一种跳帧。
- 进出场依靠门、道路和遮挡，移动路径有落脚点。特效跟动作发生的位置对应，不总从屏幕中央炸开。

## 画面怎么活

- 角色偶尔换一帧重心或衣摆，脚底位置基本不动；动作间留停顿。
- 窗光或火焰小幅变化，附近表面跟着受光，远处不一起闪。
- 水面、蒸汽或枝叶用低密度循环，周期错开，保留像素簇而非连续模糊噪声。

## 镜头语法

| 镜头运动 | 表达什么 | 适合哪类内容 |
|---|---|---|
| 小幅横移，前景产生视差 | 场景有纵深 | 世界介绍、探索 |
| 跟随角色穿过遮挡 | 身处其中 | 旅程、过程、发现 |
| 从地面稍稍抬高 | 当前地点与路径关系 | 地图、整体、结论 |
| 固定机位，光或角色改变 | 环境中的细微事件 | 情绪、循环、停留 |

## 声音调色板

第 1 档可用 FM、拨弦、柔和铺底与少量芯片音色，让画面保留像素记忆而不局限于八位音效。需要钢琴、弦乐或环境采样时，用第 2 档 Tone.js 配合授权素材。脚步按实际接触点出现，远近声随场景层级变化；口播时减掉频繁的拾取提示。

律动与和声（举例，不止这些）：缓慢探索的分解和弦、明快的行进节奏，或夜间稀疏的电子氛围。冒险、日常、工业场景可以用不同配器，不复制现有游戏旋律。

## 原生手法

- 像素角色从暗处走入灯光，脚下阴影同时变化：适合角色与世界的初次建立（经典）。
- 前景树干或立柱擦过镜头，露出相连的新空间：适合旅程和连续转场。
- 把平面地图逐层立起，角色落到对应路径上：适合进入世界和空间解释。
- 景深从一个角色移到远处目的地：适合目标、期待和叙事交接。
- 像素特效落地后变成场景中的实体细节：适合能量、建设和状态变化。

## 变化空间

- 结构：跟一个角色经过几处地点；同一场景随时间改变；从环境细节拼出全貌。
- 开场：先听见或看见局部动作；前景遮挡被让开；从二维图案进入立体场景。
- 结尾：角色抵达后留一个安静动作；抬高视角看到来路；灯光或路径回到可循环状态。

## 坑

- 全屏马赛克取代像素设计：检查角色轮廓和色块是否在原始分辨率下成立。
- 精灵投出矩形影子：阴影遵守透明轮廓，或改用有意设计的接触影。
- 脚底滑动或悬空：对齐地面、位移和姿态周期。
- 镜头转到精灵侧面露馅：限制角度，或准备对应方向帧。
- 近景锐利但远景不停闪：减少远处纹理频率，检查最终视频中的运动采样。
- 泛光与景深吞掉像素：保住当前主体边缘，只软化次要区域。
- 多来源素材像素大小不一致：先统一单位尺度和色组，再进入场景。
