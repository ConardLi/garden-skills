# 验收与审片

两件事，分开做：

| | 技术检查 | 审片 |
|---|---|---|
| 判断什么 | 文件对不对：能否解码、尺寸、帧率、时长、帧数、音轨、黑帧、响度、峰值、循环接缝 | 好不好看、好不好听、有没有达成 brief |
| 谁来判 | 程序（`inspect.mjs qa`，PASS / FAIL） | 人。Agent 先看图写出观察，**用户终审** |
| 结果 | 有任何 FAIL 都不能交付 | 记录问题和修改，已知问题如实告诉用户 |

**自己打的分不能代替验收。**Agent 看到的是抽帧图，不是真正播放的视频，也听不到声音。审片记录是帮用户更快地看片，不是替用户下结论。

---

## 1. 技术检查

```bash
node <skill>/scripts/inspect.mjs qa <slug>/out/final.mp4 --out <slug>/qa/final \
  --expect-size 1920x1080 --expect-fps 30 --expect-duration 16 \
  --audio required          # 有声片；无声片用 --audio none
  # 循环片再加 --loop（接缝那一步要和普通帧间的一步一样平滑）
```

| 检查 | FAIL 条件 |
|---|---|
| 文件能解码 | 读不到视频流，或者帧数为 0 |
| 尺寸 / 帧率 / 时长 | 和 `--expect-*` 不一致（时长允许 ±1.5 帧） |
| 帧数 | 和时长 × 帧率相差超过 2 帧 |
| 音轨 | `required` 时没有音轨，或者 `none` 时却有音轨 |
| 黑帧 | 出现任何黑帧段 |
| 响度 / 真峰值（有音轨时） | 超出 −14 ± 1.5 LUFS，或真峰值 > −1 dBTP |
| 循环接缝（`--loop`） | 最后一帧 → 第一帧的 SSIM 比它两侧的普通帧间步（倒数第二 → 最后、第一 → 第二）低 0.03 以上，且低于 0.97。最后一帧本来就比第一帧早一帧，所以快速运动的循环首尾帧不会完全一样，比较的是「这一步跳没跳」 |

没传的规格项（尺寸、帧率、时长、音轨）会列成 `NOT CHECKED`，结尾也不会说「全部通过」。这时不算验收，要按 brief 的规格重跑。`sh build.sh` 会用顶部的 `FPS / SIZE / AUDIO / LOOP` 和 `timeline.js` 的 `DUR` 自动带齐。

参数写错（比如 `--audio requried`、`--expect-size 1920*1080`）会直接报错退出，不会悄悄跳过那一项检查。

另外：`render.mjs` 发现帧数不对、页面报错、编码器退出时，会直接失败，不留下任何输出；`--determinism` 必须通过。`build.sh` 在出片之前自动跑一次（`DETERMINISM=0` 只在草稿时跳过）。

## 2. 审片

`qa` 同时会给出审片材料：`-sheet.png`（24 格抽帧）、`-phone.png`（信息流尺寸）、冻结段、切点、音频的波形图和频谱图。冻结段落在 `timeline.js` 的 `HOLDS` 里会标成「intended hold」；其余的都要判断是不是空拍，刻意的就补进 `HOLDS`，不是的就修。写了 `DROPS` 时，音频部分还会给出每个重拍前的呼吸凹陷。快速动作、转场、记忆点处，再用 `inspect.mjs strip --at <秒>` 看连续帧。

还有两份量出来的线索，同样不判 PASS / FAIL，看完自己下结论：

- **按镜头的运动**（`qa` 和 `inspect.mjs motion` 都会打印；`timeline.js` 有 `SHOTS` 时按镜头分，没有就按硬切分段）：每个镜头里每一帧步有多少画面在变（moving）、多少帧步完全不变（still）、有几次突然的跳变（jumps）。重点看三种提示：「nothing moves」（不在 `HOLDS` 里的长时间不动）、「sudden jumps」（整屏噪点隔几帧重新生成一次，读起来就是闪；或者某一帧穿帮）、「every other step is still」（步进动画，或者镜头也被步进了）。另外单独列出 **flash frames**：某一帧和前后两帧都不一样、前后两帧却一样，多半是一帧闪白、一帧空画面或一层东西漏画，除非是刻意的单帧频闪。一连串紧挨着的整屏大变化会单独列成 **rapid whole-frame changes**：快速蒙太奇是刻意的；笔触、噪点、纹理隔几帧整屏重新生成一次，看起来就是闪。
- **文字框景**（`render.mjs --text-check`，`build.sh` 默认会跑，结果在 `qa/text.json` 和 `qa/text-t<秒>.png`）：字被画面边缘切掉（CUT；展示级大字出血记为 BLEED，多半是刻意的）、两串不同的字叠在一起（OVERLAP）、竖屏字落进平台 UI 会盖住的上下安全区（SAFE）、字小到手机上读不出（TINY）。持续 ≥ 0.3 秒才报，每个时刻出一张标了框的图。它看得到 Canvas 2D 和 DOM / SVG 的字，看不到 WebGL 纹理和图片里的字，这些帧要自己看。

逐项写观察，**不适用的写「不适用」**：

| 项 | 看什么 | 什么时候不适用 |
|---|---|---|
| 开场 | 前 1 秒有没有抓住人的东西 | — |
| 节奏与密度 | 变化密度是否符合用途和风格；有没有无意的空拍；有没有呼吸 | — |
| 运动质感 | 是否符合风格的运动规则（弹簧 / snap / 步进 / 周期）；快速运动是否卡顿 | — |
| 构图与可读 | 主体大小、留白；文字在手机尺寸下能否读清、停留是否够长；`--text-check` 标出的每一处 | — |
| 内容与数字口径 | 画面完美、内容错的情况：数字、单位、名称和用户给的一致吗？倍数的说法对吗（「涨了 9 倍」和「涨到原来的 9 倍」不是一回事）？图上的数能不能算出画面说的结论？柱子从 0 开始吗，纵轴截断时写明了吗？示意数据标了「示意」吗？展开、换镜之后计数有没有从 0 重来？ | 没有事实、数据和图表的片子 |
| 记忆点 | 有没有一个清楚的记忆点，做得是否干净 | 用途本身不需要的（比如纯循环背景） |
| 风格一致 | 所选风格（或改造 / 混搭 / 自定义规则）是否从头守到尾；有没有落入禁止清单；混搭时那根贯穿的线是否清楚 | — |
| 有没有落成俗套 | 对照风格文件「最俗的版本」：画面和声音是不是基本照着它来的？brief 里挑的信号真的出现在画面上了吗？换一个主题，这支片子的画面还能原样套上去吗？能套上去，说明它没有从主题出发 | 用户明确要经典版 |
| 音画关系 | 撞击、切点、音效是否对齐；drop 前的留白 | **无声作品** |
| 完成度 | 闪烁、穿帮、文字重叠、结尾 | — |

记录到 `qa/review_log.md`：

```markdown
## 第 N 轮
技术检查：全部 PASS（或列出 FAIL 项）
审片观察：
- 开场：…  - 节奏与密度：…  - 音画关系：不适用（无声）
最严重的 3 个问题：
1. [4.2–5.0s] 卡片形变是匀速的，和「极简界面」的弹簧规则不符 → 改用 springTo { freq: 2.4, damp: 0.75 }
2. …
重渲范围：2.0–9.0s
仍未解决（交付时告诉用户）：…
```

修完只重渲出问题的那一段（`render.mjs --start --duration --out out/seg.mp4`），没问题后再出整片，并重新跑技术检查。一般要两三轮，但目标是解决问题，不是凑一个分数。同一类问题连着三轮都没修掉、两种修法都不管用，就别再在这一段上磨了，回到 brief 换做法（换技术、换镜头、换结构），或者如实告诉用户。

### 独立审片（宿主支持子 agent 时）

做片子的人自己看了三遍也看不出的问题，一个没参与制作的人往往第一眼就看出来：动作重复了几遍、两个元素重叠成一个怪东西、字读成了另一个词。宿主能派子 agent 时，交付前派一个只看成片材料的审片 agent：

- **给它的**：`qa/` 里的抽帧图、手机尺寸图、关键处的 `strip` 连续帧、`--text-check` 的标记图、音频的波形和频谱图，加上 brief 里的「观众记住的一句话」和禁止清单。**不给**代码、制作过程和你自己的审片记录，免得它跟着你的思路走。
- **让它交回的**：按严重程度排的问题清单，每条带时间码、看到了什么、它猜的原因；以及它最不确定的三处。
- **怎么用**：它的结论和你自己的审片分开记进 `review_log.md`，修完再让它看一次，区分「旧问题修好了」和「新发现的问题」。它说「缺一个记忆点、缺一个梗」，就把这条转给用户判断；要往片子里加东西，先问用户。
- 宿主没有子 agent 时跳过这一步，审片表照常由你来写。不管有没有这一步，都不能代替用户自己看片。

## 3. 常见问题和修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 画面卡、像幻灯片 | 快速运动没有模糊；步进时镜头也一起步进了 | `--subframes` 或画拖影；镜头保持平滑 |
| 整屏在闪（motion 报 sudden jumps 或 rapid whole-frame changes） | 笔触、噪点、纹理每隔几帧整屏换一次种子 | 笔触和颗粒的位置固定，让方向、亮度这类参数随 t 连续变化；手绘抖动只给线稿和小区域；胶片颗粒交给 `--grain` |
| 某一帧一闪（flash frames） | 某一帧漏画了一层、画了空画面，或者某个时间窗只有一帧宽 | `inspect.mjs frames <video> <秒>` 看那一帧；检查那个时刻前后的 `seg()` 窗口和图层顺序 |
| 撞击声先到、画面后到 | 转场从拍点开始，新画面过几帧才露出来；镜头冲击只加在新层上 | 用 `revealOn(hit, dur, reveal)` 倒推转场起点；冲击加在整个舞台（recipes.md 第 14 节） |
| 签名转场被看成普通擦除 | 时长太短，缓入缓出的两头看不出变化 | 复杂转场给 0.45–0.6 秒，`strip --at` 确认中段读得出 |
| 年代 / 媒介切换时主角姿势跳一下 | 每段按段内时间重演动作 | 贯穿元素的动作按全片时间算（mixed-media-era.md） |
| 字发糊 | `will-change`；画布没按 DPR 设置；素材分辨率低 | 去掉 will-change；`setupCanvas`；2× 素材；`--dpr 2` |
| 新旧文字叠在一起 | 容器里的内容没有单独的进场和出场 | 旧内容先模糊淡出，新内容延后进场 |
| 大字看起来像乱码、重影 | 字压在同色的繁忙内容（体块侧面、粒子、阵列）上，不是字体或代码问题 | 先单独关掉内容层渲一帧确认字本身没问题；再给字划禁入区，用取景中心或主体轮廓让开（stack.md 第 4 节） |
| 前几帧字体不对 | READY 设得太早 | `await loadFonts()` 之后再设置 READY |
| 文字突然消失 | 动画参数算出了 NaN（比如空的或无限长的时间窗） | 用 `seg()`（不会产生 NaN）；给离场时间用 `null` 而不是 `Infinity` |
| WebGL 层全黑 | 着色器编译失败；没开 `preserveDrawingBuffer` | 编译失败就抛错；先渲一帧确认 |
| 重渲的一段对不上 | 状态、随机数、计时器 | 用 `--determinism` 定位 |
| 看起来很「AI」 | 深色 + 居中大字 + 渐变 + 发光 + 同时淡入 | 回到风格文件（`styles/<slug>.md`）的规则和 brief 的禁止清单 |
| 太闹、太累 | 没有层次，没有呼吸 | 减少微变化；在 drop 前留白 |
| 结尾突然断掉 | 没有落版；音乐在小节中间被截断 | 落版停 ≥ 1.5 秒，或者做无缝循环；时长取整小节 |
| 声音轰、发闷 | 低频太多 | 见 sound.md 第 9 节 |

## 4. 交付清单

- [ ] `inspect.mjs qa` 技术检查全部 PASS，没有 NOT CHECKED（参数和 brief 的规格一致；用 `sh build.sh` 最省事）
- [ ] `--determinism` 通过
- [ ] 事实、数字、名称和用户提供的一致；不确定的已单独列出
- [ ] 文字在手机尺寸下可读，没有溢出或重叠（`qa/text.json` 里每一条都看过，刻意的出血、微注释在审片记录里写明）
- [ ] 按镜头的运动和 flash frames 都看过：没有不在 `HOLDS` 里的空拍、没有意外的闪帧
- [ ] 素材和字体的授权已列出
- [ ] `qa/review_log.md` 写明了审片观察、改了什么、还剩什么问题
- [ ] `brief.md`、`build.sh`、`out/final.mp4`、`out/poster.png` 都在项目目录里
- [ ] 交付说明里请用户自己看一遍成片（有声片要打开声音）
