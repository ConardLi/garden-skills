# 验收与审片

两件事，分开做：

| | 技术检查 | 审片 |
|---|---|---|
| 判断什么 | 文件对不对：能否解码、尺寸、帧率、时长、帧数、音轨、黑帧、响度、峰值、循环接缝 | 好不好看、好不好听、有没有达成 brief |
| 谁来判 | 程序（`inspect.mjs qa`，PASS / FAIL） | 人。Agent 先看图写出观察，**用户终审** |
| 结果 | 有任何 FAIL 都不能交付 | 记录问题和修改，已知问题如实告诉用户 |

**自己打的分不能代替验收。**Agent 看到的是抽帧图，不是真正播放的视频，也听不到声音。审片记录是帮用户更快地看片，不是替用户下结论。

---

## 1. 技术检查

```bash
node <skill>/scripts/inspect.mjs qa <slug>/out/final.mp4 --out <slug>/qa/final \
  --expect-size 1920x1080 --expect-fps 30 --expect-duration 16 \
  --audio required          # 有声片；无声片用 --audio none
  # 循环片再加 --loop（首尾帧 SSIM 必须 > 0.97）
```

| 检查 | FAIL 条件 |
|---|---|
| 文件能解码 | 读不到视频流，或者帧数为 0 |
| 尺寸 / 帧率 / 时长 | 和 `--expect-*` 不一致（时长允许 ±1.5 帧） |
| 帧数 | 和时长 × 帧率相差超过 2 帧 |
| 音轨 | `required` 时没有音轨，或者 `none` 时却有音轨 |
| 黑帧 | 出现任何黑帧段 |
| 响度 / 真峰值（有音轨时） | 超出 −14 ± 1.5 LUFS，或真峰值 > −1 dBTP |
| 循环接缝（`--loop`） | 首尾帧 SSIM ≤ 0.97 |

另外：`render.mjs` 发现帧数不对、页面报错、编码器退出时，会直接失败，不留下任何输出；`--determinism` 必须通过。

## 2. 审片

`qa` 同时会给出审片材料：`-sheet.png`（24 格抽帧）、`-phone.png`（信息流尺寸）、冻结段（它是刻意的停留还是空拍？）、切点、音频的波形图和频谱图。快速动作、转场、记忆点处，再用 `inspect.mjs strip --at <秒>` 看连续帧。

逐项写观察，**不适用的写「不适用」**：

| 项 | 看什么 | 什么时候不适用 |
|---|---|---|
| 开场 | 前 1 秒有没有抓住人的东西 | — |
| 节奏与密度 | 变化密度是否符合用途和风格；有没有无意的空拍；有没有呼吸 | — |
| 运动质感 | 是否符合风格的运动规则（弹簧 / snap / 步进 / 周期）；快速运动是否卡顿 | — |
| 构图与可读 | 主体大小、留白；文字在手机尺寸下能否读清、停留是否够长 | — |
| 记忆点 | 有没有一个清楚的记忆点，做得是否干净 | 用途本身不需要的（比如纯循环背景） |
| 风格一致 | 所选风格（或改造 / 混搭 / 自定义规则）是否从头守到尾；有没有落入禁止清单；混搭时那根贯穿的线是否清楚 | — |
| 音画关系 | 撞击、切点、音效是否对齐；drop 前的留白 | **无声作品** |
| 完成度 | 闪烁、穿帮、文字重叠、结尾 | — |

记录到 `qa/review_log.md`：

```markdown
## 第 N 轮
技术检查：全部 PASS（或列出 FAIL 项）
审片观察：
- 开场：…  - 节奏与密度：…  - 音画关系：不适用（无声）
最严重的 3 个问题：
1. [4.2–5.0s] 卡片形变是匀速的，和「极简界面」的弹簧规则不符 → 改用 springTo { freq: 2.4, damp: 0.75 }
2. …
重渲范围：2.0–9.0s
仍未解决（交付时告诉用户）：…
```

修完只重渲出问题的那一段（`render.mjs --start --duration --out out/seg.mp4`），没问题后再出整片，并重新跑技术检查。一般要两三轮，但目标是解决问题，不是凑一个分数。

## 3. 常见问题和修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 画面卡、像幻灯片 | 快速运动没有模糊；步进时镜头也一起步进了 | `--subframes` 或画拖影；镜头保持平滑 |
| 字发糊 | `will-change`；画布没按 DPR 设置；素材分辨率低 | 去掉 will-change；`setupCanvas`；2× 素材；`--dpr 2` |
| 新旧文字叠在一起 | 容器里的内容没有单独的进场和出场 | 旧内容先模糊淡出，新内容延后进场 |
| 前几帧字体不对 | READY 设得太早 | `await loadFonts()` 之后再设置 READY |
| 文字突然消失 | 动画参数算出了 NaN（比如空的或无限长的时间窗） | 用 `seg()`（不会产生 NaN）；给离场时间用 `null` 而不是 `Infinity` |
| WebGL 层全黑 | 着色器编译失败；没开 `preserveDrawingBuffer` | 编译失败就抛错；先渲一帧确认 |
| 重渲的一段对不上 | 状态、随机数、计时器 | 用 `--determinism` 定位 |
| 看起来很「AI」 | 深色 + 居中大字 + 渐变 + 发光 + 同时淡入 | 回到风格文件（`styles/<slug>.md`）的规则和 brief 的禁止清单 |
| 太闹、太累 | 没有层次，没有呼吸 | 减少微变化；在 drop 前留白 |
| 结尾突然断掉 | 没有落版；音乐在小节中间被截断 | 落版停 ≥ 1.5 秒，或者做无缝循环；时长取整小节 |
| 声音轰、发闷 | 低频太多 | 见 sound.md 第 7 节 |

## 4. 交付清单

- [ ] `inspect.mjs qa` 技术检查全部 PASS（参数和 brief 的规格一致）
- [ ] `--determinism` 通过
- [ ] 事实、数字、名称和用户提供的一致；不确定的已单独列出
- [ ] 文字在手机尺寸下可读，没有溢出或重叠
- [ ] 素材和字体的授权已列出
- [ ] `qa/review_log.md` 写明了审片观察、改了什么、还剩什么问题
- [ ] `brief.md`、`build.sh`、`out/final.mp4`、`out/poster.png` 都在项目目录里
- [ ] 交付说明里请用户自己看一遍成片（有声片要打开声音）
