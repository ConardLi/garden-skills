# 用途：拍什么、按什么结构讲

这份文件只讲**用途**：要传达什么、按什么结构讲、需要哪些素材、有哪些坑。画面长什么样、怎么动、配什么声音属于**风格**，见 `styles/INDEX.md`。同一个用途可以配不同风格，比如 Logo 演绎既可以做成瑞士编辑风，也可以做成像素 CRT。

先找到对应的那一类，**只读那一节**。结构只是起点，具体内容要从用户的主题里来。

| 用途 | 一句话 | 典型时长 / 画幅 | 常配风格（只是常见搭配，不是限制） |
|---|---|---|---|
| A 动效作品集 | 展示动效功力，手法密集切换 | 12–20 秒 · 16:9 / 1:1 | swiss-editorial、kinetic-brutalist、particle-field、glitch-digital、comic-pop、mixed-media-era |
| B 产品宣传短片 | 用真实的界面和卖点讲清一个产品 | 15–30 秒 · 16:9 / 9:16 | minimal-ui、dark-keynote、glass-material、isometric-infographic、flat-vector、soft-organic |
| C UI 动效演示 | 一个元素连续变成一串界面状态 | 10–16 秒 · 1:1 | minimal-ui |
| D 动态排版 / 金句卡点 | 字就是画面，跟着节拍走 | 8–30 秒 · 9:16 / 16:9 | kinetic-brutalist、swiss-editorial、editorial-collage、risograph-print、comic-pop、glitch-digital |
| E Logo 演绎 / 片头 | 一个想法，最后落成 logo | 4–8 秒 · 16:9 | 任意，常见 liquid-shader、particle-field、glass-material、cinematic-title、guochao |
| F 循环动图 | 没有开头和结尾，可以无限播放 | 4–12 秒 · 1:1 / 9:16 | generative-geometry、liquid-shader、pixel-game |
| G 数据爆点 | 一个数字或一组对比的冲击力 | 6–15 秒 · 9:16 / 16:9 | data-motion、swiss-editorial、dark-keynote |
| H 绿幕人物 + 代码场景 | 用户提供人物素材，场景和特效用代码做 | 10–20 秒 · 9:16 | 任意，常见 editorial-collage、kinetic-brutalist、comic-pop |
| I 年代回顾 | 按时间讲一段演进史，每个阶段换一种媒介 | 45 秒–2 分钟 · 16:9 | mixed-media-era、cinematic-title、painterly |
| J 口播讲解 / 分章长片 | 按用户原稿或录音组织图形讲述 | 按确认时长，最长 20 分钟 · 16:9 / 9:16 | 按主题选择，可沿用全部风格 |

## A 动效作品集

刷屏最多的一类，原始提示词通常只有一句「做一条 15 秒的动效视频，像简历里的作品集，全力以赴」。上限很高，但结果不可控。这一类的做法是把「全力以赴」翻译成具体的结构。

- **结构**（8 小节）：Hook（第一拍就有强烈的图形动作）→ 2–3 段不同手法（排版、界面、几何或粒子），每段 2 小节 → 加速 → 吸气 → 记忆点 → 落版（名字或一句话），或者无缝回到开头。
- **要点**：每段换一种手法，但配色、字体、运动性格要跟着所选风格贯穿全片，否则就成了模板合集。段与段之间的转场要从内容里长出来（craft.md 第 5 节）。
- **坑**：手法越多越容易散；每段只有约 2 秒，文字只能放 1–3 个词；最后一定要有落版。

## B 产品宣传短片

- **素材先行**：产品截图、UI、logo、真实的功能名和卖点。用户给的是网址或代码仓库时，可以用 Playwright 截取真实页面（2× DPR），记下元素坐标，让镜头推到真实的按钮上。**不编功能、数据、客户和评价**，缺了就问或者留空。
- **结构**（16 小节，约 30 秒）：Hook（问题或反差）→ 产品亮相 → 3 个卖点（每个都配界面镜头、一句话、一个证据动作，比如数字跳动或流程走一遍）→ 汇总 → 落版（logo + slogan + 网址或日期）。15 秒版本只保留一个卖点。
- **技术**：截图做成漂浮的屏幕，用光标点击驱动界面状态变化。多场景长片可以用 Remotion，但只在用户要求或已经在用时才用；默认单个 HTML。
- **坑**：截图推近后发糊；文字太多；品牌色被改。

## C UI 动效演示

参照公开的「界面变形」提示词模板：全片只有一个元素，从头到尾不切镜头。

- **结构**：8–12 个界面状态排在节拍网格上，例如：按钮 → 加载 → 对勾 → 播放器 → 进度条 → 滑块 → 开关 → 标签页 → 图表 → 命令面板 → 通知 → 回到按钮。
- **技术**：同一个容器改尺寸、圆角、颜色（recipes.md 第 3 节）；光标真的在拖（第 4 节）；指示条的前沿和后沿分开（第 2 节）。容器里切换的内容要有自己的进场和出场。
- **坑**：被缩放的文字加了 `will-change` 会变糊；新旧文字叠在一起；循环接缝处光标的位置或速度对不上。

## D 动态排版 / 金句卡点

- **结构**：文案拆成「一拍一个词」或「一小节一句」，重点词放在重拍上。整句出完后要停留到读得完（craft.md 第 7 节）。
- **技术**：Canvas 或 DOM；逐字遮罩进场（recipes.md 第 1 节）。竖屏要把字排在安全区内。
- **坑**：词太多、停留太短；中文字体没做子集，渲染时出现方块。

## E Logo 演绎 / 片头

- **结构**（4–8 秒）：预备（暗示 logo 的元素）→ 爆发 → 成形 → 定格（logo + 品牌名，停留 ≥ 1.5 秒）。
- **素材**：**必须用真实的 logo 文件**，SVG 最好，可以拆路径做描边或分块组装。拿不到就停下来问，不要用色块冒充。
- **坑**：logo 的比例或颜色走样；定格太短。

## F 循环动图

- **结构**：一次完整的呼吸（聚 → 散 → 聚），最后一帧等于第一帧。
- **技术**：所有运动都写成 `θ = TAU * t / DUR` 的整数倍频率函数，噪声在圆上采样（recipes.md 第 11 节）。不要用逐帧累积的模拟。
- **验收**：`inspect.mjs qa … --loop`（或 `LOOP=1 sh build.sh`），接缝那一步（最后一帧 → 第一帧）要和普通帧间的一步一样平滑。声音可以没有；有的话，声音也要能循环。

## G 数据爆点

- **结构**：铺垫（问题或对比的一方）→ 数字滚动（1.5–2.5 秒）→ 落定（撞击或反色）→ 一句解释（停留 ≥ 2.5 秒）→ 来源（小字）。
- **技术**：计数器（recipes.md 第 9 节），配等宽数字；对比用尺寸表达，柱子从 0 开始长。
- **坑**：**数字只能来自用户或可靠来源**，不确定就标出来让用户核对。

## H 绿幕人物 + 代码场景

代码画不好写实人物和复杂动作，所以让视频模型只负责人物，其余全部用代码做。

1. 用户用视频模型（Seedance、可灵、即梦、Grok 等）生成人物片段：**纯绿背景**、全身入镜、不出画。这一步由用户完成，本 Skill 不调用视频模型。
2. 抠像：`ffmpeg -i dancer.mp4 -vf "chromakey=0x19FF0A:0.16:0.08,despill=type=green,format=yuva444p10le" -c:v prores_ks -profile:v 4444 dancer_alpha.mov`。颜色值从抽帧里取，先抠一帧检查边缘。
3. 背景、大字、贴纸、分屏用代码渲成一层视频，按节拍变化。
4. 合成：`ffmpeg -i bg.mp4 -i dancer_alpha.mov -filter_complex "[0][1]overlay=(W-w)/2:H-h" …`。人物前面需要元素时，把人物导出成图片序列，在页面里按 t 选帧绘制。
5. 交付时写清哪些画面来自视频模型、哪些来自代码。

## I 年代回顾

参照公开传播的代码版「电子游戏发展史」：2 分钟、多种媒介混搭、合成配乐，画面跟着音乐剪。

- **结构**：开场（一个能贯穿全片的元素，比如一个像素点、一个光点、一个词）→ 4–7 个阶段，每段 8–20 秒，每段用那个阶段的媒介来画 → 高潮（所有阶段汇合）→ 结尾（呼应开场）。
- **要点**：一根贯穿全片的线（同一个主角、同一种转场、一首配器逐段升级的配乐）。没有这根线，就成了风格拼盘。构图骨架每段对齐，贯穿元素的动作按全片时间走，转场借下一个媒介自己的出现方式，可以一路加速。风格规则见 `styles/mixed-media-era.md`。
- **制作**：超过 60 秒时先做低清小样（`--size 960x540`）确认整体节奏，再按段落分别精修；渲染慢的段落（3D、着色器）单独用 `--start --duration` 测试。
- **坑**：**史实必须准确**：年份、名称、首创者都要核实，不确定的就不写，列给用户确认。

## J 口播讲解 / 分章长片

- TTS 原稿必须由用户提供；也可用用户录音，或制作没有口播的分章长片。此用途不负责把文章代写成口播稿。
- 有口播时先准备真实音频和句段时间戳，用语义、停顿和重点组织画面，再配 BGM 与音效；无口播时仍保留音乐节拍驱动。详见 `narration.md`。
- 长片可以按章节改变构图和镜头密度，保留共同的字体、色彩和图形含义。不要把短片每拍换画面的密度强行拉满整片。
- 最长 1200 秒；与用户指定时长冲突先确认。超过 2 分钟按 `long-form.md` 分章构建、缓存和审片，保留旧短片全部技术与风格能力。
