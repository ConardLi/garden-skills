# 实做笔记：哪些做法被一支真片子证明有效

这份文件只记**做对了、而且有证据的事**。坑写进对应文件的「坑」或 review.md 的常见问题，这里不重复。每支片子交付后（SKILL.md 第 7 步）花几分钟回看一遍：哪一招让片子明显变好了？有证据就记一条。

规则文件（craft.md、styles/）告诉你「应该怎么做」，这份笔记记「这样做了，结果怎样」。后来的人照着某条做成功了，就在那条的证据里加一笔；照着做失败了，写清边界。一条做法被三支以上的片子证实、而且换风格也成立，就把它提炼进 craft.md 或对应的风格文件，这里留一行指过去。

## 每条怎么写

```markdown
### <一句话的做法，能直接照着做>
- 证据：哪支片子（slug）、第几秒、改之前什么样、改之后什么样；能量化就写数字（inspect / audio check / text-check 的输出、帧差、dB、毫秒）。
- 为什么有效：一两句，讲清机理，不要只说「更好看」。
- 什么时候用：适用的用途、风格；什么情况下不适用。
- 来源：<日期> · <slug>（之后复用成功的，追加在这一行后面）
```

## 写之前想一下

- **放哪里**：只对一个风格成立的，写进那个风格文件（运动、画面怎么活、原生手法、坑）；换风格也成立的，记在这里；能让程序量出来的（比如「拍点那一帧整屏有变化」），考虑做成 `inspect.mjs` 或 `render.mjs` 的检查，做成工具后文档里的规则就可以删短。
- **不写什么**：用户的素材、品牌信息、未公开的产品细节、个人反馈原话都留在项目目录里，这里只收可复用的方法和必要的证据。
- **不要替用户加东西**：审片时发现「缺一个梗」「缺一个记忆点」，记下来交给用户判断；结构性的改动先在风格帧或样片里给用户看，用户点头再加。

## 条目

### 阶段交接要检查接触、缩放和旋转，不能只检查位置

- 证据：`offbeat-note`《逃跑的音符》，3.75 秒由蓄力转为腾空，11.25 秒落地。初版重心接得上，身体宽高与手脚位置却换得太快；加入伸展过程、接触端点衔接和连续旋转后，起跳与落地连续帧能读出完整过程。最终逐镜头检查没有检出突然跳变或闪帧。成片和连续帧见仓库根目录 `motion-samples/offbeat-note/`，用户听感与播放节奏终审仍待完成。
- 为什么有效：镜头中间的单张姿态看不出交接问题；接触点和轮廓的前后变化，决定观众能否看懂离地、抓住和落下的过程。
- 什么时候用：角色表演，以及吸附、拖拽、拼装等有明确接触与释放的图形动效。纯色彩渐变不需要套用肢体检查。
- 来源：2026-10-24 · `offbeat-note`，15 秒、1920×1080、30fps。
